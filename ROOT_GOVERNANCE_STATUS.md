# ROOT Governance Status — Current Authority and Regional Rollout

**Effective date:** August 11, 2026  
**Status:** Current operating decision; revise only through an explicit First Executive review.

## Current Authority Decision

ROOT will operate with **one active First Executive account** at this stage. The business identity remains the sole authority-bearing operator record. The owner’s personal ROOT code is retained as a private identity reference inside the same signed-in account; it is **not** a second account, independent operator principal, or source of inherited business authority.

This is the least-complex and least-privileged option for the current pilot. Creating a second operator principal from a second code under the same account would create the appearance of separation without a separately revocable sign-in, distinct accountability boundary, or independent authentication event. ROOT therefore preserves a clear rule: a distinct operator requires a distinct signed-in member account.

| Question | Current decision |
| --- | --- |
| Business operating authority | One active First Executive operator record. |
| Owner’s personal ROOT code | Private identity reference only; visible in the owner’s signed-in Member Gateway. |
| Additional operator created in this rollout | No. The duplicate business-identity Directory Steward draft was declined and audited. |
| Distinct personal operator principal | Deferred. It requires a genuinely separate member account and an explicit, least-privilege approval packet. |
| Automatic role inheritance | Prohibited. A personal identity card receives no operator, directory, publisher, employer, or partner authority. |

## Conditions for Revisiting a Separate Personal Operator

A distinct personal operator should be considered only when one of the following conditions is actually present: the individual uses a separate signed-in ROOT account; the proposed duty must be independently suspended or revoked; the role requires a separate conflict disclosure; or the regional operating model needs a separately accountable Directory Steward or Incident Reviewer. At that point, the proposed account must submit a private operator intake with a member code, role-facing label, narrow role, regional scope, conflict disclosure, and review date.

> **Governance rule:** A second label is not a second authority. Independent authority requires independent authentication, explicit approval, a bounded scope, an audit trail, and a revocation path.

## Project Reclaim Regional Rollout

Project Reclaim is integrated as a source-governed ROOT program across **Health, Housing, Work, Education, Community, and Independence**. ROOT lists reviewed public pathways; it does not make hiring, placement, housing, clinical, benefit, or outcome decisions. A listed source is not a partnership claim.

| Region | Current status | Records | Authority boundary |
| --- | --- | --- | --- |
| Mendocino County | Active Project Reclaim pilot coverage. | CalWORKs Job Services (Work); Community Development Commission (Housing). | Both are published only because active A1 is reviewed and county-matched. Their official source URLs and quarterly review dates are retained. |
| Lake County | Private source-monitoring watchlist. | Lake County Housing; Lake County Behavioral Health Services. | Neither record is public, neither has a node assignment, and neither represents active ROOT coverage or an implied relationship. |

Lake County publication is blocked until all of the following are true: a reviewed active Monarch node has a Lake County regional label; a First Executive reviews the primary source and current availability; the record is assigned to that active county-matched node; and the record is explicitly changed from an internal watchlist to published state. In particular, a closed public program remains a source-monitoring record, not an advertised opportunity.

## Member Privacy Boundary

Members may save a private Project Reclaim interest note against a published source. The note remains in the member-owned ledger and does not appear in the public Project Reclaim page, in the source-control panel, or in the Project Reclaim audit ledger. It is not forwarded to a county agency, provider, employer, or partner unless the member later creates a separate explicit grant.

## Near-Term Operating Sequence

The immediate focus is to maintain the Mendocino County source review clock and monitor Lake County sources privately. Before any Lake County public launch, ROOT should approve a real regional mandate, identify a distinct accountable operator if needed, validate current availability through primary sources, and use the existing First Executive publication gate. No fictional jobs, estimated openings, inferred partnerships, or unverified regional services should be introduced.
